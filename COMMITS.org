* 007

#+begin_example
007 feat: implement load_csv execution
#+end_example

Added the first concrete manifest mode.

=load_csv= now:

- resolves the source CSV relative to the manifest
- recreates the package DuckDB database for each run
- creates or replaces the declared target relation
- loads CSV data with DuckDB =read_csv_auto=
- reports the loaded row count

Added =duckdb= to =requirements.txt= and added CSV execution fixtures/tests.


* 008

#+begin_example
008 feat: implement run_sql execution
#+end_example

Added the second concrete manifest mode.

=run_sql= now:

- resolves SQL files relative to the manifest
- reads UTF-8 SQL text
- rejects empty SQL files
- executes SQL against the current DuckDB connection
- allows later SQL layers to depend on relations created by earlier steps

The SQL file owns the names of any views or tables it creates.

Added a Prepared-layer SQL fixture and tests.


* 009

#+begin_example
009 feat: implement export_sql execution
#+end_example

Added the third concrete manifest mode.

=export_sql= now:

- accepts a relation name or SELECT/WITH query
- resolves output paths relative to the manifest
- creates parent output directories
- exports CSV with a header
- reports the exported row count

The sample manifest now runs the complete path from CSV source through SQL
transformation to CSV export.

All three manifest execution modes are now implemented.
